Last updated: 2025/12/23

If you have suggestions for changes or questions, please open an issue on GitHub.

First, thank you so much for taking the time to contribute! ❤️

This document explains how you can contribute code to MoFox_Bot, or participate in development in other ways, including development of plugins. 

We encourage and value all forms of contribution, but unorganized contributions will only make MoFox's maintenance and updates chaotic. Therefore, we recommend reviewing this guide before making your contribution.

> Also, if you like this project but simply don't have time to contribute, that's okay too. There are other simple ways to support the project and show your appreciation that we'd also be very happy with:
> - Give us a star ⭐
> - Reference this project in your project's README

## I Have a Question

> If you want to ask a question, we assume you have already read the existing documentation.

Before asking a question, it's best to search existing [issues](/issues) to see if anyone has already helped solve a similar problem. If you find a matching issue but still need to add clarification, you can comment on that issue. We also recommend searching the internet for answers first.

If you still think it's necessary to ask and need clarification, we recommend you:

● Open a [new issue](/issues/new) and describe your problem in as much detail as possible.

● Provide as much context information as possible to help us better understand the problem you're facing. For example: provide version information (which branch, version number, runtime environment, etc.) based on what you think is relevant.

As long as your issue is clear and reasonable, we will respond and try to solve it.

## I Want to Contribute

> ### Project Ownership and Maintenance
> The MoFox_Bot project (modified from MaiBot, core is MaiCore) was created by 雅诺狐 and uses GPL3 open-source license.
> The MoFox_Bot project has been moved to the MoFox_Bot organization, and is currently maintained by the core development team, with overall maintenance shared between the core development team, reviewers, and all contributors (this will be clarified in the future).
> To ensure unified design, save unnecessary effort, and maintain overall control of the project, we adopt different review strategies for different types of contributions:
>
> #### New Features
> - Definition: Adding new functionality, architecture adjustments, important module refactoring, etc.
> - Requirements: Generally not accepted for now; you can submit an issue to suggest new features.
>
> #### Bug Fixes
> - Definition: Fixing errors in existing functionality, including unexpected behavior (which needs to be confirmed by opening an issue) and runtime errors, without involving new features or architectural changes
> - Requirements: Must be confirmed by core team members or 2 or more reviewers before merging
> - Closure: PRs that include expected behavior changes, new features, breaking existing functionality, or destructive database changes will be closed
>
> #### Documentation Updates
> - Definition: Fixing errors in existing documentation, providing new help documentation
> - Requirements: Must be submitted to the docs repository under the organization and merged after reviewer confirmation

> ### Legal Statement
> When contributing code/documentation to this project, you must confirm:
> 1. Your contribution is 100% created by you;
> 2. You have the corresponding rights to this content;
> 3. Your contribution will be used according to the project's license agreement.

## Making Suggestions

This section guides you on how to submit a suggestion to MoFox-Core, including brand new features and minor improvements to existing functionality. Following these guidelines will help maintainers and the community understand your suggestion and find related ones.

Before Submitting a Suggestion

● Make sure you are using the latest version (check the master branch for official release, dev branch for beta).

● Make sure you have read the documentation to confirm whether your suggestion has already been implemented, perhaps through separate configuration.

● Carefully read the documentation and understand whether the project currently supports this feature, perhaps it can be implemented through separate configuration.

● Do a [search](/issues) to see if anyone has already made this suggestion. If so, add a comment to the existing issue rather than opening a new one.

● Make sure your suggestion fits the project's scope and goals. You need to make a strong case to convince the project developers of the feature's benefits. Remember, we want features that are useful to most users, not just a few. If it's only for a few users, consider writing a plugin.
